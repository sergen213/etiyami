# ETI Yami recovery

## Delivered native engine

`native/` is a C++20 reconstruction; `build/yami-native` is the working Linux executable. It loads the original assets and compiled scripts directly. It does **not** launch Wine, the original executable, or `son.eti`.

The implementation includes all four levels, the 40-opcode script VM and 20 script hosts, model/mesh/animation loaders, CPU skinning, body/flight physics and collision, player controls, five enemy AI families, combat, pickups, mission callbacks, level transitions, the original menus/quizzes/HUD, settings, checkpoints, video/audio, and the native ending dialog/code generator. The original 32-bit VM words, animation ordinals, callable registration order, and 33 ms tick rules are retained rather than translated into host-pointer-sized values.

Linux execution is verified on COSMIC Wayland and X11 with OpenGL and OpenGL ES, and Vulkan execution is verified on x86_64 Wayland with local source and installed public packages. **v1.1.1** adds Vulkan artwork/history/ray-position corrections and optional Desktop publication while retaining v1.1.0's enhanced GL/GLES character shadows. Its native Ubuntu 22.04 x86_64/ARM64 builds, publication, all-six package validation, installed x86_64 gameplay, genuine installed-v1.1.0 update, unchanged Apps launch and post-close preservation checks passed within the documented limits, including a small music-value serialization change. Historical v1.1.0 and public 1.0.4 installer evidence remains separate below. **v1.3.0 expands release scope to Windows x86_64** with the same engine/renderers and a per-user offline installer; macOS remains deferred. Platform-specific verification and its limits are recorded below; no blanket behavioral-parity certification or complete human campaign playthrough is claimed.

## Build and run

Dependencies: a C++20 compiler, CMake 3.20+, Ninja, pkg-config, SDL3, libepoxy, libxml2, FFmpeg development libraries (`libavformat`, `libavcodec`, `libavutil`, `libswscale`, `libswresample`), libcurl 7.85+, libarchive, and json-c. FFmpeg must include the Indeo 5 decoder. The optional Vulkan backend additionally requires SDK headers, `glslangValidator` or `glslc`, and Python 3 at build time. Curl supplies verified HTTPS, json-c parses GitHub metadata, libarchive safely reads update ZIPs, and FFmpeg's SHA implementation verifies download integrity. Neither the bundled DirectX installer, proprietary Indeo installer, FMOD DLL, nor Wine is needed.

On Arch/CachyOS:

```sh
sudo pacman -S --needed gcc cmake ninja pkgconf sdl3 libepoxy libxml2 ffmpeg curl libarchive json-c vulkan-headers glslang python
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build
./build/yami-native --width 1600 --height 900
```

`YAMI_ENABLE_VULKAN` defaults on only when headers and a shader compiler are found. `-DYAMI_ENABLE_VULKAN=ON` requires those prerequisites and Python 3; `-DYAMI_ENABLE_VULKAN=OFF` builds the retained OpenGL/GLES engine without them. GLSL is compiled for Vulkan 1.3, then `tools/embed_spirv.py` generates `yami_vulkan_shaders.hpp` in the build directory. Raster/UI and effects/RT variants share source but have distinct embedded SPIR-V; the non-RT effects variant contains no ray-query operations. Runtime needs no shader files or shader compiler. SDL loads the distribution's Vulkan loader only when Vulkan is constructed; application executables do not link `libvulkan` as `DT_NEEDED`.

Assets are discovered relative to the executable (`game/`, then the development tree's `../game/`), with the current directory's `game/` as a final fallback. macOS also checks `game/` beside the `.app` for Finder launches, independent of the working directory. An explicit `--asset-root /path/to/game` is used exactly and must contain `data/menu/menulist.xml`. SDL supplies UTF-8 executable/preference paths, including macOS bundle Resources. The asset tree is read-only; checkpoints and `game.ini` go to `SDL_GetPrefPath("ETI", "YamiNative")`, or an explicit `--save-dir` outside the asset tree.

Controls: WASD/arrows move; mouse controls the camera and the original menu cursor; Ctrl/left mouse fires; Space performs the special action; E/Enter interacts; Tab shows objectives; Escape opens the game menu; F11 toggles fullscreen. Mouse capture is released on focus loss and during the ending dialog, with held input cleared before reacquisition.

Optional flags: `--fullscreen`, `--renderer opengl|vulkan`, `--gles` (OpenGL ES), `--samples 4`, `--anisotropy 16`, `--skip-intro`, `--level 1` through `--level 4`, and `--capture output.ppm`. OpenGL remains the default backend. `--help` lists the interface. Linux prefers Wayland when available; `SDL_VIDEO_DRIVER=x11` explicitly selects X11.

Enhanced graphics are on by default. Effect strengths are independently adjustable in `0..1`: `--ao 0.65 --reflections 0.22 --bloom 0.12`. In v1.1.1, `--sharpen 0.18` applies only to OpenGL/GLES and remains a saved but dormant preference in Vulkan. Zero disables the applicable effect; nonfinite/out-of-range values are rejected. `--classic-graphics` restores the recovered lighting and disables world effects while retaining widescreen layout, MSAA, and texture filtering.

Vulkan controls, available since public v1.1.0: `--ray-tracing on|off`, `--taa on|off`, `--shadows 0..1`, `--gi 0..1`, `--exposure 0.1..4`, `--render-scale 0.5..1`, and `--roughness 0.05..1`. Defaults are RT/TAA on, shadows 0.75, one-bounce indirect lighting 0.35, exposure/render scale 1, and global roughness 0.85. All numeric values must be finite and within bounds. Shared AO/reflection/bloom controls retain their backend-specific implementations. v1.1.1 makes sharpening OpenGL/GLES-only, with its saved/CLI preference retained but inactive in Vulkan; preferences are not reset. Vulkan-only values persist while OpenGL/GLES is active but do not modify its rendering. Classic Vulkan bypasses HDR effects, RT, TAA and reduced render scale, preserving native-resolution recovered lighting/legacy gamma.

### Ayarlar graphics controls

The original **Ayarlar** screen now has a right-hand parchment graphics panel, using the game's original bitmap font, blue/red buttons, hover artwork, and background. Existing brightness, sensitivity, sound, aiming knobs, and Back remain in their original locations. The original asset files are not modified.

- **Işıklandırma:** classic or enhanced lighting/world effects.
- **Ortam gölgesi, Yansımalar, Parlama, Keskinlik:** AO, rough-surface reflections, bloom, and sharpening strengths; each active control click changes five percentage points, bounded to 0–100%. OpenGL/GLES uses screen-space AO/reflections; Vulkan can use hardware ray queries. In v1.1.1, **Keskinlik** is OpenGL/GLES-only, has an explicit inactive caption and cannot be adjusted in Vulkan; its saved preference is retained. Loaded/CLI values are retained until edited. Classic mode retains these values but does not execute the effects.
- **Yumuşatma:** MSAA off or a GPU-supported quality level. **Doku filtresi:** anisotropic filtering from 1× to 16×, bounded by GPU support. Live OpenGL/GLES changes preserve the GL context and scene assets; only MSAA render targets are reallocated, and filtering updates already-uploaded world textures. Vulkan updates its own targets/samplers rather than switching backends.
- **Tam ekran:** fullscreen on/off, synchronized with F11 and completed SDL fullscreen events, including asynchronous Wayland transitions.
- Public v1.1.0 includes Vulkan RT, TAA, shadow/indirect strengths, exposure, render scale, and roughness controls through **Vulkan seçenekleri**; **OpenGL / Genel** returns to the shared panel. The advanced page states when its controls are inactive under OpenGL/GLES or RT is unavailable. The backend selector is exposed in the launcher only; the in-game panel cannot switch the active backend.

Native buttons change on mouse release, not hover or repeated held frames. Changes apply immediately and are saved by atomic temporary-file replacement. Original held knobs save on release; Back and normal window close also save. Five-line legacy settings files remain readable. Native `game.ini` appends validated `grafik_*` fields; invalid, duplicate, or unknown extensions are rejected. Saved graphics settings load before renderer creation; explicit CLI flags override only their corresponding saved fields. The effective settings are saved on normal exit, including dormant Vulkan preferences when GL is active. Window dimensions follow resize; OpenGL/GLES/Vulkan remains a launch-time selection.

### Native asset-based launcher

```sh
./build/yami-launcher
# Same interface through the direct executable:
./build/yami-native --launcher
```

The launcher uses the original Ayarlar artwork, bitmap fonts, dials, parchment graphics panel, and game artwork rather than host-native or web controls. It exposes the original settings, native graphics settings, and current source backend/Vulkan controls. Both interfaces share the settings parser, bounds, hardware capabilities, and atomic file replacement; there is no second launcher configuration file.

The launcher starts windowed on the retained OpenGL path (GLES with `--gles`) even when Vulkan/fullscreen is saved. **Tam ekran** selects the game's launch mode without taking over the desktop while editing settings. **OYNA / PLAY** saves settings, destroys launcher scene resources before their renderer, then creates a fresh window/renderer and `SceneCache` for the chosen backend before entering gameplay. GL context-bound resources never transfer into Vulkan. Audio registration, intro playback, game VM initialization, and level loading happen only after Play. Vulkan initialization failure recreates the launcher with a visible explanation to choose OpenGL; gameplay never silently falls back. A GL-only build permits a saved Vulkan preference to be changed to OpenGL in the preview. Closing saves settings without starting the game. CLI overrides seed the controls; subsequent launcher edits take precedence. Tab/Shift-Tab selects setting rows or Play/Close, arrows change values, Enter/Space activates, and Escape closes; keyboard focus is visibly outlined. `--no-launcher` bypasses the interface, and `--smoke` always bypasses it.

For a portable installed layout with original data:

```sh
cmake -S . -B build -DYAMI_INSTALL_ORIGINAL_ASSETS=ON
cmake --build build
cmake --install build --prefix /path/to/yami-distribution
```

The install target includes launcher, game, and update helper, original `game/data`, the original EULA/icon, and macOS bundle Resources when targeting Apple. It excludes the old Windows executables, Wine reference, legacy DLLs, and bundled codec/DirectX installers. Asset installation is opt-in; redistribution still requires the appropriate asset rights. Third-party runtime-library packaging is handled by the release workflow; platform installers and Apple notarization are separate requirements.

```sh
  mingw-w64-ucrt-x86_64-pkgconf mingw-w64-ucrt-x86_64-python \

```

Windows uses native SDL input/audio/video, WGL OpenGL/GLES and SDL-loaded Vulkan. Libepoxy receives each external WGL context transition. Frame-generation presentation uses `SDL_DelayPrecise` rather than the coarse Windows sleep quantum. Menu XML opens through UTF-8 paths. FidelityFX uses the Windows CRT declarations on MinGW and explicit standard headers; its pinned MIT notice is an RC-data resource in `yami-native.exe`, keeping the update ZIP flat.

`tools/package_release.py` validates PE32+ architecture and recursively collects every non-system DLL. `tools/package_windows_setup.py` combines that engine ZIP, the GUI setup, statically linked removal helper, official pinned 7-Zip 26.04 archiver/SFX and license notices into `yami-setup-windows-x86_64.exe`. Verification rejects changed SFX/configuration, truncated/corrupt payloads, unexpected files, missing DLLs, wrong architectures, missing licenses, non-static removal dependencies, and any engine-byte mismatch. Packages are unsigned; SmartScreen publisher warnings are expected and are not bypassed by the installer.

The initial UCRT64 cross-build compiled all engine/launcher/updater/test targets with Vulkan and FSR enabled. The real asset sweep then passed **984 models, 3,947 meshes, 141 animations and 2,523 materials with zero errors** after normalizing Windows' case-insensitive path identity in the check. Windows Python produced and validated a flat **109-file** engine ZIP; the packaged engine ran on a clean DLL search path. Actual gameplay under Wine completed **123 level-2 ticks** in OpenGL, Vulkan RT-off, and Vulkan RT/FSR/frame-generation modes. OpenGL used isolated Xvfb software rendering; Vulkan used the host RX 7900 XTX through Wine's Wayland driver and produced inspected real/generated captures. Wine emitted a pointer-warp protocol error after the successful Vulkan smoke, so these observations establish Windows code execution, not native-Windows desktop or driver certification. Native `windows-2022` CI and public-release proof are recorded separately when completed. MSVC remains unverified; macOS is deferred.

### Public GitHub project and updates

Repository: [sergen213/etiyami](https://github.com/sergen213/etiyami), **public**. Git tracks the native source, build/release configuration, recovery utilities, existing technical notes, and selected visual evidence. Proprietary `game/` data, installer archives/executables, Wine state, build products, and credentials remain local and excluded.

The launcher checks GitHub releases in the background before Play. Version checks use `vMAJOR.MINOR.PATCH`; only a newer complete asset matching the native OS/architecture is eligible. Downloads use verified HTTPS and GitHub's authenticated asset endpoint. The SHA-256 digest from GitHub must match before bounded extraction; traversal, links, conflicting paths, and original/user-data targets are rejected. A detached copy of `yami-updater` replaces launcher, game/engine binaries, and their bundled runtimes with backup/rollback, then restarts the launcher with the same asset/preferences paths. Settings and original assets are not part of updates.

Public releases can be checked and downloaded without a GitHub account or token. Optional per-user `YAMI_GITHUB_TOKEN`, `GH_TOKEN`, or `GITHUB_TOKEN`, or an existing local `gh auth login` credential, also work. Tokens are never built into the application or written to update files/command arguments. If this updater is configured for a private repository, grant a fine-grained token **Contents: read** only for that repository.

Environment-based authentication is inherited by the trusted update helper and restarted launcher so it survives an automatic restart. It is never serialized into the package or staging directory. The helper uses null standard streams and a private diagnostic log.

Missing releases, inaccessible metadata, offline operation, or a non-writable installation produce a visible status; the current installed game remains launchable. Closing cancels a pending check/download. `--no-updates` explicitly disables network checks, `--version` prints the installed binary version, and direct game/smoke execution does not check updates.

`.github/workflows/release.yml` builds Linux x86_64/ARM64 and Windows x86_64 packages without proprietary assets. The publication contract is exactly eight assets: six Linux ZIP/`.run`/AppImage files plus `yami-windows-x86_64.zip` and `yami-setup-windows-x86_64.exe`. Every ZIP contains the three launcher/game/updater executables and application dependencies; installers additionally carry the GUI setup, standalone remover, and a trusted archiver for offline ISO extraction. Ubuntu 22.04 jobs retain the glibc 2.35 ceiling, flat `$ORIGIN` layout, and host-owned glibc/C++/graphics runtimes. Windows uses UCRT64 and bundles application/MinGW runtime DLLs while retaining OS graphics drivers. CMake embeds `YAMI_RELEASE_VERSION` and `YAMI_UPDATE_REPO`; the source default version is **1.3.0**. Tagged CI overrides it with the stable release tag. macOS jobs remain deferred.

AppImages combine architecture-matched, fully static uruntime 0.8.1 with a SquashFS installer payload and automatic extraction fallback when FUSE is unavailable. `--appimage-extract-and-run` explicitly requests no-FUSE execution. The `.run` alternative uses standard shell/tar/gzip/coreutils. Neither format includes the original game artwork, font, icon, or data. Packaging checks enforce payload membership, architecture, host-library exclusions, and the glibc ceiling; those checks are not evidence of physical ARM64 GPU/gameplay execution. ### Linux original-ISO installer

`native/setup_assets.cpp` reads the selected original ISO's MSI/CAB content without executing Windows programs. MSI table mapping selects 9,032 native assets (637,554,001 bytes), excluding legacy executables and codec/DirectX installers. `native/setup_main.cpp` uses SDL native file/folder dialogs and cancellable background work; Tab/Shift+Tab, Enter/Space, and Escape provide keyboard operation. Before installation, nine allowlisted menu/material/image/font files are extracted into a private temporary preview and validated by `native/setup_artwork.cpp`; original artwork is never embedded in public binaries. The preview is removed on cancellation/exit.

`native/setup_install.cpp` privately stages original assets, three native engine executables/application libraries, the root `uninstall.sh`, and `.eti-yami-uninstall/yami-remove`; it converts the ISO's original icon to PNG and publishes the installation plus play/uninstall application-menu/Desktop shortcuts with ownership checks and rollback. It refuses root execution, unrelated existing destinations/shortcuts, links, unsafe paths, and malformed or oversized input. A valid inventory-bearing reinstall keeps existing engine/assets/settings and repairs shortcuts/removal support without needing the original ISO or engine source files. Legacy format-1 roots without inventories require the original ISO to prove asset paths/bytes; unproven files/libraries are retained rather than claimed by scanning the live tree. Cancellation does not publish a partial fresh installation. Default storage is `${XDG_DATA_HOME:-$HOME/.local/share}/etiyami`; preferences remain in SDL's separate per-user location.

**v1.1.1** makes Apps / application-menu entries the required launch path and Desktop files optional. A missing, disabled or unusable Desktop, including a regular file at its path, or an unrelated Desktop shortcut collision can be skipped with a warning while core installation and owned application-menu repair succeed. Optional publication failure is tolerated only after safe rollback; incomplete rollback retains recovery backups and fails with a manual-recovery error. Core/application-menu conflicts still fail closed. This does not enable Desktop icons or change desktop/user preferences; older v1.1.0 installers require Desktop publication. Binary support remains glibc 2.35+ on x86_64/ARM64 with standard FHS shell/environment paths, XDG application support, and host C++/graphics runtimes, not universal musl/non-FHS or all-desktop compatibility.

Build `yami-setup` to run the source GUI with `--engine DIRECTORY --archiver /absolute/path/to/7zz`. Its dependency builds the SDL/FFmpeg-free, stdlib/POSIX-only `yami-remove`, and CMake copies the matching `uninstall.sh` beside the setup binary. `InstallRequest.remover` defaults to `SDL_GetBasePath()/yami-remove`; `--remover FILE` selects an alternate helper whose parent also contains the script. The optional real-ISO regression is `check_setup_install ISO ENGINE 7ZZ REMOVER NEW_ISOLATED_DIRECTORY` (build target `check_setup_install`); it exercises extraction, cancellation, safe publication, owned reinstall/legacy provenance, and both shortcut pairs in an isolated directory. The `uninstall` CTest invokes `check_uninstall HELPER SCRIPT`, linking only the standard C++ runtime.

The root `.eti-yami-install` format-1 marker remains unchanged. `.eti-yami-installed-files` records exact installer-created file paths and owned shortcut paths; `.eti-yami-engine-files` records validated engine payload filenames. Successful trusted updates maintain/merge that engine inventory locally without adding a fourth executable or manifest to the update ZIP. Manual ZIP installations never acquire uninstall authority merely by updating.

The uninstall shortcut has `Terminal=true` and invokes `/usr/bin/env -- /bin/sh` with the escaped installed script path. The script derives its own root and invokes the private helper; it never requests `--yes`, sudo, a download, a GUI, or an ISO. Interactive removal requires a terminal, shows the exact root and preserved-data policy, and defaults to cancellation. Only recorded ownership is removable; save/settings/unknown files survive and remaining files are reported. Only empty recorded child directories are pruned; the installation root is always retained, even when empty. Invalid/missing ownership metadata fails closed. Removal metadata/support and shortcuts remain until late in the operation. The helper depends only on host glibc/C++ libraries, not the engine/SDL/FFmpeg runtime.

Security boundary: removal trusts the installing/current UID and unsigned private ownership inventories. Private `0700` storage and the cooperative updater lock exclude other-user access and concurrent cooperating product writers. No-follow descriptor-relative traversal, root/parent/mount identity validation, preflight, and checked recovery detachment guard path substitution. Linux `unlinkat` remains name-based, not inode-conditional: a malicious same-UID process able to modify the private recovery namespace is outside this guarantee. No hostile-same-UID deletion guarantee, privileged/root helper, or protective namespace is claimed.

Both installer formats include this complete support pair offline. `.run` validation checks required members, exact executable/nonexecutable modes, matching script bytes, helper architecture/glibc floor/host-only dependencies, closed application-library membership, and byte-for-byte agreement with the paired engine ZIP. AppImage verification inherits that verified payload and checks exact SquashFS membership/modes/bytes. New regressions mutate real support members rather than mock command output. Existing pinned archiver/runtime caches, attribution/notices, corresponding-source policy, and original-asset exclusions remain unchanged.

The installer self-test also extracts its verified real removal ELF into private temporary storage and injects `DT_NEEDED` entries with `patchelf`: the matching x86_64/ARM64 glibc loader must pass (including real `--help` execution on the native architecture), while the opposite architecture's loader, SDL3, and `libGL` must fail with the exact rejected name. This checks the host-only boundary without broadening it to GPU/application libraries.

### v1.2.1 source follow-up — FSR 3.1.4 upscaling and frame generation replace artwork TAA

- **Device:** FSR requires formatless storage-image writes, compute quad subgroups and storage RGBA16F/RG16F/R32F/R32UI. Frame generation additionally needs compute arithmetic subgroups, formatless storage reads and an RGBA8 display image usable as storage, sampled, attachment and transfer source/destination.
- **Frame:** after the temporal lighting denoiser, a render-resolution pass composes the linear HDR world exactly as the display pass did before (artwork × (gain + AO × Sun) + reflection, sampled from the current denoised native-resolution illumination at each jittered sample's unjittered position) and converts the sample-zero prior-UV metadata to RG16F UV motion. FSR runs with `ENABLE_HIGH_DYNAMIC_RANGE`; jitter uses `ffxFsr3UpscalerGetJitterOffset` in the engine's pixel convention (`lowResUV = uv + jitter/renderSize`), `motionVectorScale` is the render size, near/far/FOV come from the Vulkan projection, and history resets with the lighting history. Bloom and tone mapping then read the FSR output; **Keskinlik** drives RCAS. The first integration upscaled only the unlit artwork and multiplied illumination in afterwards, so RT Sun/AO/reflection edges stayed aliased and flickered — the user observed jagged edges only with ray tracing on.
- **Reactive mask (moving shadows):** a box sliding over static textured ground left a long trail of its old RT Sun shadow with FSR on (frame generation off) and none with FSR off: the ground's motion vectors are zero while its shading changes, so FSR kept accumulating the old shadow inside its wide rectification box. The FSR inputs pass now also writes, per render pixel, `log2` of an illumination factor `I = lum(gain + AO·Sun) + lum(reflection)/max(lum(artwork), 0.05)` (the lit/artwork ratio for grey light, taken from the denoised unjittered terms so jittered artwork cannot fake a change; the floor keeps black artwork on the composed term) and its clip W (linear view depth) into a ping-ponged render-size RG32F history. It reprojects with its own UV motion, takes the nearest previous texel's 3×3 neighbourhood restricted to the same surface (stored depth within 2 % of this surface's previous clip W, from the raster metadata or camera reprojection), and writes R8 `reactive = 0.9·smoothstep(0.25, 0.75, distance of log2 I outside that neighbourhood's [min, max])`. A full-strength Sun shadow scales illumination by 0.3–0.5 (|Δlog2| 1.0–1.7, fully reactive); denoised AO/GI/reflection move a few per cent per frame (< 0.25, untouched), and sub-pixel jitter at static shadow or texture edges stays within the neighbourhood range. Invalid history (FSR reset, size change, lighting-history reset), off-screen or disoccluded samples write 0. The same mask is also passed as FSR's transparency & composition mask to drop locks there. In a throwaway moving-shadow probe (static checker ground, 12 px/frame) the trail's RMSE against the FSR-off frame fell from **0.0465 to 0.0237**; a faint residue remains for a few frames because reactive is capped at 0.9. Shadows moving under one render pixel per frame stay inside the neighbourhood range and are left to FSR.
- **Sun on the FSR input: per-sample rays + clamped visibility TAA:** users still saw moving shadows jump. In a scratch probe, a hard shadow edge sliding at a constant ~1.1 px/frame advanced in irregular steps (standard deviation of the per-frame step **0.97 px** native, **1.23 px** Kalite; many 0-px stalls followed by 3–4 px jumps), because the FSR input used the fixed-grid Sun visibility, which is constant across the sub-pixel jitter, so FSR could not place the edge between texels. Under FSR the Sun pass now traces every render sample's own jittered surface point (its boundary ray), and the FSR input composes with that per-sample visibility while the reactive-mask illumination keeps the texel Sun (so jitter cannot fake a shading change): step deviation **0.48 px** native, **0.72 px** Kalite, stalls mostly gone. The remaining irregularity came from the reactive mask itself, which (to stop moving-shadow trails) drops FSR's history on moving shadows, so each frame showed a freshly aliased jittered edge. `sun_taa.comp` therefore filters the per-sample visibility alone before FSR, in the `--gpu-timings` `fsr-inputs` row, when RT Sun is on and FSR upscales: per render sample, v is the Sun pass's traced visibility (1 where none was traced; samples whose raster token is negative are not filtered), its previous position comes from the raster metadata (previous UV and clip W), else from camera reprojection, exactly as the FSR motion vectors; the previous filtered value is read bilinearly at that position in the previous frame's jittered sample grid (texel c at unjittered (c + ½)/size − previous jitter), keeping only taps whose stored clip W is within 2% of the surface's previous clip W; it is clamped to the min/max of v over the current 3×3 neighbourhood and blended as `mix(clamped, v, 0.15)` (a constant weight). Visibility has no texture, so the clamp box is no wider than the edge itself and the history cannot trail. History is a ping-ponged render-size RG32F (filtered visibility, clip W) pair, like the reactive history (R32 keeps clip W exact at any range; R32G32 storage is core Vulkan); it restarts whenever FSR restarts its own history (reset, resize, lighting-history reset, settings change; the first frame) or the previous frame did not run the filter. FSR-off, RT-off, classic and OpenGL/GLES paths are unchanged. Measured with the filter (same probe, edge step standard deviation left/right edge): native 0.21/0.40 px, Kalite 0.46/0.44 px, Performans 0.59/0.37 px, with no stalls; the fast-moving-shadow trail against FSR off is unchanged (RMSE 0.0259 vs 0.0248). Tracing every sample also skips the Sun pass's 9×9 boundary-halo search: at Kalite the level-2 smoke's median `sun` row fell from 2.86 to 1.12 ms.
- **Frame generation:** following IKV, optical flow and frame interpolation are dispatched by hand on the HUD-less tone-mapped composition, reusing FSR's dilated depth, dilated motion and reconstructed previous depth. The HUD is drawn onto both the generated and the real frame. While active, a present thread owns presentation: it presents the generated frame, waits until half the measured frame interval after the frame became ready, then presents the real frame (IKV's extra 2 ms lead is dropped: below the 165 Hz cap a variable-refresh display shows each image when presented, so the lead split every rendered interval about 40/60 — 7.3/11.3 ms at 54 fps — while the content advances by equal halves, a judder most visible on moving shadows); all queue use is serialised and at most one job is outstanding. After a history reset only the real frame is shown. Moving shadows were doubled in generated frames: one game motion vector per pixel carries the surface, not the shadow moving over it, so the game-vector path cross-fades the old and new shadow. Deterministic walking captures showed this mostly on the moving character itself: the shirt/bag shading looked layered and striped wherever the body moved into or out of a bag, arm or car shadow, and was clean with Sun shadows off. The shading change also lowers the game path's colour similarity, so interpolation leaned on its optical-flow path, whose 8×8 block vectors tear a small moving character into block-sized fragments. An earlier local patch that raised the game-vector bias exponent from 1 to 8 (it halved the cross-faded share in a static-ground probe) strengthened exactly that and is reverted. **Shading-change mask (local SDK patch, README item 7):** frame interpolation takes an optional render-size mask, here the FSR reactive mask (`0.9·smoothstep(0.25, 0.75, |Δlog2 I|)` of the same surface point between the two real frames, so it also marks a walking character's own body). In `computeInterpolatedColor`, where the current game-vector sample is valid (inside the current frame and not disoccluded), `m` is the maximum of the mask over the 6×6 render texels around that sample (`uv − gameMotion`; the 2×2 bilinear footprint dilated by two texels, because the mask's own 3×3 previous-range tolerance leaves the texel or two at the old shadow edge unmarked), `w = smoothstep(0, 0.3, m)`, the game-vector colour becomes `lerp(upstream game colour, selected real frame's game-vector sample, w)` and the game-vector bias `lerp(bias, 1, w)`: the correctly placed surface gets one shadow instead of two and the optical-flow path stays out. With a zero mask interpolation is exactly upstream, and real frames are untouched (walking captures: at most 14 pixels differ by ≤2 levels, the same as two runs of one build). With the mask alone (every point takes this frame's sample), measured on RX 7900 XTX/RADV, 2560×1440, deterministic time, private compositor: in the shadow-sliding probe the cross-faded share of the swept band fell from 62% to 1.6% (textured ground) and 21% to 2.1% (plain); in walking captures with only the RT Sun active, generated-frame half-strength shadow regions at least 5 px across, beyond the two real frames' average, fell from 3875 to 360 px (character moving into a shadow) and 1600 to none, and the bag/shirt shows one shadow instead of a layered one. All 17 CTests and Khronos validation with synchronisation checks (Native AA, Performans with frame generation) passed. In 74 minutes of play the user found the doubling gone but the shadows stepping at the real-frame cadence. **Midpoint selector:** for a hard Sun shadow moving one way, every point it sweeps is, halfway between the frames, either still in its current state or still in its previous one, and interpolation's game-vector path already samples both real frames at that surface point, so a per-point choice reuses real rendered pixels: FSR's lag in recently changed shading and the texture are never rescaled. (1) Every RT instance carries its previous pose (the last submitted skinned vertex buffer and model that the raster motion metadata already uses; the current ones for draws without a predecessor). For the Sun pass's fixed-grid ray and its boundary ray, the same ray query that decides visibility returns the committed triangle; with s the ray's receiver point, n its physical normal, L the Sun direction, D = b′ − b the blocker point's (barycentric) motion from the previous to the current pose and d the receiver's own displacement (its raster metadata position through the previous camera rays minus its current reconstruction, zero without metadata), the previous shadow point is s′ = s + D − L·n·(D − d)/n·L (Zeng et al., *Temporally Reliable Motion Vectors for Real-time Ray Tracing*, 2021, §4.1). Expressed on the current receiver it is q = s′ − d, and a second, RGBA16F Sun-pass target stores r = uv(q) − uv(s) under the unjittered current view-projection, valid only for hits (the fixed-grid ray's when both hit) of perspective frames with history while frame generation is active; it is zero otherwise, and Sun visibility is unchanged. (2) After the temporal and FSR passes, `sun_midpoint.comp` takes each lighting texel's Sun factor F (litRadiance's Sun term, its luminance where it is per-channel) and, where the Sun term is used and F < 1, splats it with an atomic minimum (float bits in an R32_UINT image cleared to 1.0 each frame) to the texels containing t + r·size/2: one texel when the shift is integral (so an unmoved shadow maps exactly onto itself), otherwise up to 2×2. Ceiling: shadows moving more than 64 lighting texels per frame relative to their receiver splat in place. (3) A second dispatch of the same shader (`-DYAMI_MIDPOINT_SELECT`) writes the render-size R8 selector `select = 1 − smoothstep(0.02, 0.15, |F_mid − F|)` (1 where the Sun term is unused): 1 keeps this frame's state, 0 the previous frame's. (4) Interpolation reads it bilinearly at the same current game-vector sample as the mask and, where `w > 0`, uses `lerp(previous game sample, current game sample, select)`, forcing `select = 1` where the previous sample is outside its frame or disoccluded. Measured on the shadow-sliding probe against a true-midpoint render (share of the swept band within 12 luma of it, textured / plain / moving plain ground): mask alone .334 / .328 / .548; an intermediate build that relit this frame's display image with the midpoint Sun factor instead .553 / .706 / .804, and .632 / .841 / .809 after solving each pixel's own factor at current shadow edges and the 6×6 mask dilation, but rescaling the current frame amplified FSR's lag in recently changed shading on texture, which this selector avoids; the selector reaches .829 / .847 / .812, and about 90% of the remaining misses lie within 2 px of the true shadow edge. In walking captures the bag/shirt shows a single shadow between its two real positions. The cost is in the `--gpu-timings` `sun` (offset output) and `display` (both dispatches) rows; with frame generation off or without RT Sun none of it runs and real frames are unchanged. Limitations: the committed blocker is the first accepted hit, not necessarily the nearest; shading changes that are not RT Sun shadows (AO, GI, reflections, light changes) take this frame's sample where the mask marks them; a soft penumbra point, in neither real state at the midpoint, gets a blend of the two samples weighted by its factor change. This replaces an earlier fallback that, after interpolation, replaced generated pixels on camera-only surfaces with the real frame warped half a frame back; it could not handle moving receivers and required a fifth FSR-inputs colour attachment (`maxColorAttachments ≥ 5`). That pass, its R8 mask and the requirement are removed.
- **Removed:** the eight-phase artwork history in `temporal.frag`, the separate artist-mask raster replay (~2.2 ms/frame measured) and its effects/temporal plumbing. Lighting-history tests that depended on the old TAA phase table were converted to TAA-off or deleted (`check_independent_sun_history`, `check_current_unsafe_variance`).
- **Sun on smooth-shaded models:** RT Sun rays used to start on the flat facet, so low-poly characters drew triangle-shaped hard shadows on facets that merely tilt away from the Sun (isolated with Sun-only versus Sun-off captures; AO/GI were already smooth). The Sun pass now fades the ray-traced shadow out over smooth authored N·L 0–0.25, where the raster material already shades the surface, and lifts the ray origin onto the curved surface implied by the hit triangle's vertex normals (Hanika, *Hacking the Shadow Terminator*, 2021), found with one camera ray only where the authored and facet normals differ. Flat geometry and cast shadows on Sun-facing surfaces are unchanged.
- **History-unsafe RT samples, compacted:** a few 16-sample pixels made whole fragment waves loop 16 times (~4.8 ms of the effects pass at 1280×720). `effects.frag` now takes sample 0, appends each such pixel's exact state (partial sums, ray origin, normals, random pair, Fresnel, `gl_FragCoord`) to a render-extent queue (96 bytes/pixel), and `effects_rt.comp` continues samples 1–15 in packed waves from the same `effects_rt.glsl` code; an indirect point draw (`effects_resolve`) writes the finished values through the same colour export. Stable pixels are unchanged. The first build compared `VkBuffer` handles to detect the queue's reallocation; RADV reused the freed handle, so the descriptor kept the freed buffer and the first queued frame page-faulted (device lost) — the Khronos layer's unique handle wrapping hid it. The set is now rewritten on a size change.
- **Ray-tracing performance:** mesh vertex/index buffers, per-draw uniforms, upload staging and the RT instance/material tables now prefer host-visible device-local memory (resizable BAR) instead of system RAM; readback stays host-cached, and animated-mesh UV checks use a CPU copy instead of reading the mapping. TLAS instances without alpha tests are `FORCE_OPAQUE`, exported face culling moved into traversal (`CullBackFacingTriangles` plus per-instance flip/disable, mask 0 for front-and-back), and Sun visibility rays stop at the first hit. - **Character pose interpolation (enhanced only):** the original poses skinned characters from 30 fps keyframes (`floor(elapsed × .001f × 30) % frameCount`) while their positions move every rendered frame, so limbs and their RT shadows snapped at 30 Hz with an uneven 2-1-2 cadence that frame generation cannot hide. - **Distance fog after enhanced lighting:** the original fog (`mix(.2, c, clamp((2000 − W)/1000, 0, 1))` in the display domain, W = view depth, every world draw on levels 1–3) is applied by the raster before the enhanced composition lights the artwork, so GI, Sun shadows, AO and reflections modulated the fog colour and far buildings looked light grey with recess detail (Vulkan RT only; OpenGL and RT-off captures showed uniform dark fog). `lit_radiance.glsl` (both the FSR input and the FSR-off display) now unfogs a partly fogged ray surface, c = (c_f − .2(1 − f))/f, lights pow(c, 2.2) as before and refogs mix(.2, lit^(1/2.2), f); f comes from the surface's clip W in the temporal geometry metadata, and the per-frame flag (`rayBasisX.w`) is set when every ray-geometry world draw is fogged. All 17 CTests and Khronos validation with synchronisation checks pass with both changes. The fog depth must belong to the artwork sample itself: the first version took it from the lighting texel, so at far silhouettes a jittered building sample next to a sky texel (or the reverse) switched between the fogged and unfogged composition from frame to frame, which FSR showed as shimmering jagged edges in the distance; the FSR input now uses the sample's own clip W and raster token. The refog is computed without dividing by f: the raster colour is .2(1 − f) + D with D = f·c for a plain surface, so .2(1 − f) + (D^2.2·composed + f^2.2·reflection)^(1/2.2) is the same result, while blended effects (pickups, glows) drawn over a fogged surface only add to D; the first version unfogged by 1/f and returned the bare fog colour at f = 0, which cut such effects off in rectangles over the fully fogged far street (seen in play).
- **Distance fade of RT ambient occlusion:** AO's fixed 10-unit rays outline every ledge and window frame of buildings down the street, which players read as visible AO and which aliases at render resolution. The composition now keeps full AO up to 200 units (about 5 m, using the sample's view depth) and fades it to none at 500 (`smoothstep(200, 500, W)`); nearer surfaces are unchanged.
- **Async present queue for frame generation:** with frame generation on, the present thread copies and presents on a dedicated queue when the GPU has another queue family that can present to the window (on RADV the compute queue), as AMD's frame-interpolation swapchain does. Before, each copy into the swapchain sat on the graphics queue behind the next frame's ~15 ms of rendering, so on a variable-refresh display the generated and real frames appeared whenever that work finished instead of at the planned half-interval cadence: judder only with frame generation on (players saw moving shadows jump). Measured in a scratch build that waited on each present copy: submission-to-completion median 6–7 ms, p90 ~18 ms before; median 0.12 ms, p90 8–15 ms after. The final frames are rendered in the swapchain's pixel format so the copy is a plain byte copy that transfer/compute queues can do; outputs are shared CONCURRENT between the two families, a timeline semaphore orders each frame's rendering before its copies, another makes a frame wait for the copies of the slot it reuses, and captures swap R/B back when the swapchain is BGRA. Without a second present-capable family the single-queue path is unchanged.
- **Animated effects in the shading-change mask:** frame interpolation only bypasses its optical flow where the FSR-inputs mask is set, and that mask measured lighting change only, so pickup glows and other blended effects (which change the raster artwork, not the lighting) were left to 8×8 optical-flow blocks that tore them over featureless fog (reproduced with an additive glow quad sliding and pulsing over fogged ground). The FSR-inputs history now also keeps log2 of each sample's artwork luminance (RGBA16F: log2 illumination, clip W, log2 artwork; clip W at half precision is ~0.05% against the 2% same-surface test), and the mask is .9·max(smoothstep(.25, .75, lighting change), smoothstep(.5, 1, artwork change)) beyond the same 3×3 previous same-surface range (artwork floored at .02 linear; the stricter artwork threshold keeps band-limited textures under jitter unmarked). In the probe the generated frame now shows the glow whole, as in the current real frame; such effects animate at the real-frame rate, and FSR drops their history instead of ghosting them.
